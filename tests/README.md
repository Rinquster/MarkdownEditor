# Тесты

Самодостаточные страницы-проверки: каждая сама себя прогоняет, пишет отчёт
в скрытый `<pre id="results">` и кладёт итог в `<title>` — `ALL-PASS` или `FAILURES-N`.
Ни сборки, ни зависимостей.

## Запуск

```
node tests/run.js                          # весь набор
node tests/run.js tests/drop-folders.html  # только указанные страницы
```

Раннер сам поднимает локальный HTTP-сервер и headless-браузер, ждёт отчёта каждой
страницы и печатает его. Путь к браузеру берётся из `CHROME_BIN`, иначе ищутся
`google-chrome`, `chromium`, `chromium-browser`.
Список страниц лежит в `tests/suite.js` — его же берёт измеритель покрытия.

## Что ещё не покрыто

```
node tests/coverage.js
```

Показывает, какие места `js/app.js` ни один тест ни разу не выполнил. Искать имена
функций в тестах бессмысленно: они работают через интерфейс, а весь код спрятан
в IIFE, — поэтому покрытие берётся у самого движка через `Profiler` протокола отладчика.
Сейчас 96%; остаток — обработчики ошибок IndexedDB, чтения файла и загрузки скрипта,
которые без порчи браузера не вызвать.

Можно и вручную — страницы обычные:

```
python3 -m http.server 8765
# затем открыть http://127.0.0.1:8765/tests/<страница>.html
```

Из `file://` часть проверок работает иначе (буфер обмена, IndexedDB), поэтому нужен HTTP.

## Что стоит знать, дописывая тесты

- **Не используйте `chrome --dump-dom --virtual-time-budget`.** Виртуальное время
  перематывает таймеры, но не ждёт IndexedDB: тест, упирающийся в запись без единого
  висящего таймера, обрывается на середине. Ровно из-за этого написан `run.js`.
- **Профиль браузера общий на весь прогон.** Страница, которой нужно чистое
  состояние, сама удаляет базу и чистит ключи `mdeditor-emergency` и `mdeditor-settings`
  в localStorage — иначе аварийный снимок предыдущей страницы подменит содержимое
  открытого файла, а её настройки зададут другой режим, и нужная панель не отрисуется.
- **Приложение падает при неполной разметке.** `app.js` берёт все узлы по id и не
  проверяет их на null: страница-фикстура обязана содержать полный набор элементов
  из `index.html`, иначе весь скрипт умрёт на первом же `addEventListener`.
- **Медиазапросы проверяются во фрейме.** Ширину окна из страницы не изменить, зато
  можно открыть `_app-frame.html` в узком iframe: медиазапрос смотрит на его окно.
  Так проверен мобильный режим в `polish.html`.
- **Раскладку проверяйте координатами, а не наличием элемента.** Панель может
  существовать и быть видимой, но стоять не там: сравнивайте `getBoundingClientRect()`
  соседних панелей. Так поймана колонка оглавления, уехавшая под превью.
- **Слой подсветки проверяется двумя числами, а не глазами.** Текст слоя обязан быть
  посимвольно равен тексту поля, а `scrollHeight` обоих — совпадать: при любом
  расхождении переносов высоты разъедутся. См. `editor-highlight.html`.
- **Синхронную прокрутку нельзя проверять «процент к проценту».** Осмысленная проверка —
  прокрутить редактор к строке конкретного заголовка и убедиться, что этот заголовок
  оказался вверху превью; см. `split-and-sync.html`.
- **Хранилище можно отнять и вернуть.** Подмена `window.indexedDB` на `undefined`
  до загрузки `app.js` проверяет работу без базы, а возврат настоящего объекта —
  что накопленное дописывается. Но пока базы нет, каждая запись оставляет липкое
  сообщение об ошибке: проверки строки состояния в этом режиме бессмысленны.
- **Записи файловой системы можно подделать.** Настоящие `FileSystemEntry` достаются
  только из `dataTransfer.items[i].webkitGetAsEntry()`, но приложение обращается лишь
  к `isFile`/`isDirectory`/`fullPath`/`file()`/`createReader()`. Как это подставить
  в синтетическое событие — смотрите `drop-folders.html`.
